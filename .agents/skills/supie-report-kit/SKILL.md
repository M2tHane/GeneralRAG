# 开发验证报告模板

复用 [templates/report-template.html](templates/report-template.html) 的内联样式和测试报告结构。浏览器可直接打开或打印，无需模板引擎。

## 使用范围

- `supie-dev` Stage 6：按主流程要求生成 `docs/06-测试报告.html`。
- `supie-edit` / `supie-fix`：默认简洁汇报改动与验证证据；只有用户或父流程确需独立报告时才生成 `docs/test/test-<主题>-<时间戳>.html`，不增加固定产物或审批关卡。
- 原型走查证据记录在既有设计记录/状态中；正式实现的验证可引用相关截图与结果，不再派生独立走查报告。

## 填写方式

1. 复制模板到父流程指定路径，修改标题、被测对象、来源流程和运行环境。
2. 根据真实证据填写测试摘要、用例与结果、需求对应关系、相邻回归、失败详情和执行命令。替换或删除所有示例数字、行和结果；无关区块可删。
3. 状态使用 `status-pass / partial / fail / todo / na`，区分通过、部分验证、失败、未做和不适用；不能把未运行记为通过。
4. 如实列出无法验证的范围、原因和阻塞。代码阅读、原型模拟和生产集成验证需明确区分。
5. 完成后检查 HTML 结构、目录锚点及截图路径，并打开浏览器检查可读性；浏览器不可用时说明视觉检查缺口。

所有结论必须来自实际观察，不能把模板中的示例或“预计通过”写成测试证据。报告只汇总验证，不替代父流程的实际测试与独立评审。
