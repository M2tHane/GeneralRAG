# 蓝白商务设计系统

在视觉设计或实现阶段读取。目标是专业、安静、可信的企业级 SaaS 工作界面：内容优先、层级清楚、信息密度适中，默认浅色并完整支持深色。

## 固定技术体系

```text
核心：Next.js App Router + React + TypeScript strict
样式与组件：Tailwind CSS + shadcn/ui + Base UI primitives + Lucide React
复杂表格：TanStack Table
客户端服务端状态：TanStack Query
表单：React Hook Form + Zod
业务图表：Recharts
```

- shadcn/ui 是项目内可维护的组件配方，Base UI 提供无样式交互原语；同一组件只采用一种 primitive 实现。
- 服务端组件为默认；交互、浏览器 API 或客户端状态才建立小而明确的 Client Component 边界。
- 服务端状态需要缓存、轮询、乐观更新或客户端协同时使用 TanStack Query。
- 业务组件使用语义 tokens，不散落任意色值和魔法尺寸。
- `components/ui` 不含业务知识；领域组件放在 `features/[domain]`。页面负责组合，不堆积请求、Schema 和复杂状态。
- 不引入 Ant Design、MUI、Chakra 等第二套完整视觉体系，不混用图标库。
- 后四项按页面实际能力使用；没有对应需求时不创建假表格、假图表或无意义客户端状态。

## 视觉基调

- 白色或近白主工作区，浅冷灰导航，单一品牌蓝作为主操作与选中强调。
- 大面积区域依靠背景、间距、对齐和 1px 边框分层；阴影只用于浮层。
- 默认圆角 8px，小控件 6px，浮层不超过 10px。
- 品牌蓝可视面积通常不超过约 10%；状态色只表达状态，不装饰页面。
- Hover 只做轻微背景或边框变化，不缩放卡片、不漂浮。
- 动效约 120～220ms，仅解释状态与空间变化，并尊重 reduced motion。

禁止渐变背景、玻璃拟态、发光、霓虹、彩色阴影、巨型 Hero、营销口号、大量彩色图标圆底、装饰插画、夸张圆角和无依据的数据图表。

Dark 使用深灰而不是纯黑，不能全局反色。菜单、Dialog、Toast、Tooltip 等 Portal 内容必须继承主题。偏好支持 `light | dark | system`，默认 System，刷新后保持用户选择并避免首屏闪烁。

## 字体、文案与间距

- 中文使用可靠的系统 CJK 字体栈；拉丁字符可用 Geist 或 Inter。不要为了个性增加展示字体。
- 页面标题 `22～24px/30～32px`，`font-semibold`；Section 标题 `16～18px/24px`。
- 中文正文优先 `15px/22px`；控件、Label、表格正文不小于 `14px/20px`。
- 辅助与元数据 `13～14px`；12px 只用于极少量非关键时间戳或紧凑标记。
- 数字、金额和时间使用 `tabular-nums`，数值右对齐，单位与精度一致。
- 以 4px 为基础尺度，常用间距为 `4 / 8 / 12 / 16 / 24 / 32`。页面边距桌面 `24～32px`、小屏 `16px`，区块间距约 `24px`。
- 控件默认高 `36～40px`；表格行高 `44～48px`，紧凑模式最低约 `40px`。

### 删除测试

每段辅助文案必须补充至少一项：数据范围/口径、非显然约束、操作后果、异常原因或恢复方法。删除后不影响理解就删除，不把它缩小、变淡或移到边角。

- 只保留一个中文页面标题；不自动添加英文 eyebrow、翻译标题或英文副标题。
- 不写“点击名称查看详情”“在这里管理你的内容”等显而易见说明。
- 不写“让工作更高效”等口号填补空白。
- 必要错误、限制、单位、权限和后果必须保留并正常可读。

## 应用外壳

- 桌面侧栏宽 `232～248px`，浅冷灰背景和右侧细边框。
- 顶栏高约 `56px`，只放必要的全局上下文与操作。
- 主内容普通页面最大宽 `1280～1440px`；数据密集页面可占满剩余空间。
- 当前导航项使用淡蓝背景、深色文字和蓝色图标，不铺高饱和蓝。
- 低频设置、帮助和账户入口放侧栏底部或独立菜单，不挤占主业务区。
- 标题区通常是“标题 + 必要状态/范围 + 次要操作 + 唯一主操作”，不是 Hero。

## 组件规则

### 操作与浮层

- 一个页面通常只有一个 Primary Button；次要操作使用 secondary、outline、ghost 或 More 菜单。
- 按钮使用明确动词。Lucide 图标通常 16px；图标按钮提供可访问名称和 Tooltip。
- Dialog 用于短任务；Drawer 仅用于依赖背景上下文的辅助任务；复杂任务进入独立页面。具体判断以主 Skill 为准。
- Dropdown 收纳低频行操作；每行最多直接显示 1～2 个高频动作。
- Toast 仅反馈低后果的短暂成功；字段错误就近呈现，系统问题使用可持续的 Alert。

### Card 与状态

- Card 默认白底、1px 边框、8px 圆角、无阴影，仅在通过 Card Gate 时使用。
- Badge 使用浅色背景、深色文字和细边框；状态用词在全产品保持一致。
- 状态不能只靠颜色表达，同时提供文本或图标。
- Skeleton 模拟真实内容结构；空状态只保留必要解释和一个合理下一步，不使用大插画。

### TanStack Table

- 首列承担对象识别；数值右对齐；长文本截断后通过 Tooltip、展开或详情查看。
- 表头低对比但清楚，不使用深色或高饱和彩色表头。
- 只启用业务需要的排序、筛选、分页、选择、列显隐、固定列或虚拟化。
- 工具栏只放搜索、1～3 个高频筛选和主操作；批量动作仅在选择后出现并显示范围。
- 大数据使用服务端排序、筛选和分页；查询条件可安全地写入 URL。
- 表格外壳支持页面高度的纵向 Flex 布局：数据区伸展，分页页脚稳定停靠在主工作区底部上方并保留 `24～32px` 底部安全间距；短数据不能让分页紧贴最后一行，分页也不能覆盖数据。
- 分页默认提供 10/20 条每页数量切换、总数、当前页/总页数和前后翻页；总页数超过 7 页或控件拥挤时增加页码输入跳转，并校验整数边界。
- 覆盖 loading、empty、filtered-empty、error。窄屏隐藏低优先级列或转字段化列表，不强行挤压。

### TanStack Query

- Query Key 使用稳定的领域层级和统一 key factory；按业务设置 `staleTime`。
- Mutation 精确更新或失效相关缓存，不全局刷新。
- 区分首次加载、后台刷新和提交中；后台刷新保留已知数据。
- 轮询只用于真实实时需求，在页面隐藏或任务终止时停止。

### React Hook Form + Zod

- 使用 Zod Schema 定义表单类型与客户端验证，服务端仍重复验证。
- Label 始终可见；帮助文字仅用于必要格式、影响或后果。
- 单列表单通常宽 `480～640px`；相关字段按业务 Section 分组，不逐组套 Card。
- 提交失败保留输入并聚焦首个错误；提交中防止重复提交并保持按钮宽度。
- 危险设置与普通设置分离并置于末尾。

### Recharts

- 一个图表只回答一个问题；数字或短表能说清时不用图表。
- 主序列用品牌蓝，比较序列用冷灰；只有类别区分确需时增加有限辅色。
- 不使用 3D、渐变和重阴影。折线看趋势、柱形做比较；饼图不超过 5 类。
- Tooltip 显示完整时间、单位和准确值；图表有文本摘要及 loading、empty、error。

## 响应式与可访问性

- 桌面优先，但 `360px` 以上必须能完成核心任务。小屏侧栏进入 Drawer，主操作保持可见。
- 复杂表格可在自身容器横向滚动，不能撑出整页；Master–Detail 在窄屏转为列表 → 详情。
- 使用语义 HTML 和 Base UI 的可访问交互；所有功能可用键盘完成。
- Focus Ring 清晰且不被错误/选中样式覆盖。不要移除 outline 后不提供替代。
- 普通文本满足 WCAG AA 4.5:1；控件边界和必要非文本状态通常至少 3:1。
- 触控目标建议不小于 40×40px；图标按钮、图表和状态点提供文字含义。
