# 需求理解与页面布局

仅在新建整页、结构性改版或信息架构问题明显时读取。目标是确定用户真正要做什么，并让默认页面只保留支持这个任务的内容。

## 页面主类型

根据用户此刻的任务选择一个主要类型，不按路由名或 SaaS 模板决定：

| 类型 | 主要任务 | 默认结构 |
| --- | --- | --- |
| Overview | 判断整体状况与关注事项 | 少量关键摘要、异常、下钻入口 |
| Work Queue | 连续处理待办或异常 | 优先级队列、处理状态、必要详情 |
| Object List | 查找、比较、管理同类对象 | 搜索/筛选、Table/List、对象入口 |
| Object Detail | 理解或管理一个对象 | 身份、关键属性、状态、相关记录 |
| Master–Detail | 在多个对象间连续切换处理 | 保持列表与选中对象上下文 |
| Editor | 创建、修改、调试或组装内容 | 编辑区、必要参数、预览或结果 |
| Investigation | 关联证据、定位原因、决定处置 | 事件上下文、证据、时间线、动作 |
| Analytics | 比较趋势、维度和分布 | 统一范围、相关分析视图、下钻 |
| Settings | 修改持久配置 | 按配置归属分组、明确保存边界 |
| Onboarding | 完成首次配置或首次有效结果 | 必要步骤、前置条件、下一步 |

一个页面只能有一个主要职责。分栏是一种布局，不是第二个主类型；列表没有数据只是 Empty State，不自动成为 Onboarding。若 Dashboard、Editor、Settings、Detail 同时竞争首屏，拆分页面或下沉内容。

页面类型取决于主要行为，而不是是否存在汇总数字。用户主要连续处理任务时，即使顶部展示少量状态数量，仍应选择 Work Queue；汇总仅是队列的筛选或辅助信息。

## 收集足够信息

检查与页面直接相关的需求、路由、组件、数据来源、提交逻辑、权限和现有约定。区分“实际观察”“代码显示”“用户明确”和“待验证”。只有截图时不推断隐藏行为，只有代码时不声称视觉走查通过。

影响方向但未知时询问：

- 谁在什么频率下使用？
- 用户主要判断什么或完成什么？
- 哪些信息改变决定，哪些只是解释？
- 操作失败的成本和恢复方式是什么？
- 典型数据量、屏幕与权限是什么？
- 设置或参数属于平台、工作区、模板、对象还是单次执行？

只问会改变设计的问题，并尽量给出可选项；其他细节说明假设后继续。

## 内容处置

对每项内容和操作做一次判断：

| 处置 | 条件 | 典型去向 |
| --- | --- | --- |
| 默认保留 | 完成当前任务必须看见或使用 | 主工作区或紧邻操作 |
| 按需展开 | 短暂使用，保留上下文有价值 | Popover、Details、Drawer |
| 下沉 | 有独立目标、长期编辑或可分享 | 详情页、二级页、Settings |
| 合并 | 重复表达同一对象或判断 | 连续 Section、单一状态区 |
| 移除展示 | 不支持判断、重复、不可解释 | 从 UI 删除；不等于删除业务能力 |

不能隐藏失败原因、阻断条件、当前筛选、权限反馈、必填字段和不可逆后果。设置是持久配置的归属，不代表每项简单设置都必须单独成页。

## 默认页面骨架

```text
Page Header       中文标题 + 必要状态/范围 + 唯一主操作
Primary Content   当前要判断或处理的对象
Secondary Content 最多 0～2 个支持当前判断的区域
Details           按需查看的解释、历史或高级操作
Settings          独立的持久配置入口
```

- Breadcrumb 只用于真实层级，不重复侧栏导航。
- 标题已表达职责时不加副标题或欢迎语。
- 搜索与 1～3 个高频筛选靠近数据；高级筛选进入 Popover/Sheet，生效条件仍需可见。
- 详情页优先“对象概要 + 平级 Tabs + 操作”；不要纵向铺开全部信息。
- 长表单按业务问题分 Section；组间距大于组内距，不给每组套 Card。
- 可分享任务使用稳定 URL；返回时保留合理的筛选、分页、滚动和选中状态。

## 任务容器决策

按顺序判断：

1. 能否在当前页面直接完成且不破坏结构？能则使用 Inline/Popover。
2. 是否是单一 Section、通常不超过 5 个简单字段、无复杂联动且约 1 分钟内完成？是则使用居中 Modal。
3. 是否必须同时参考主页面对象、队列或选择状态？是且任务轻量时使用 Drawer/Side Panel。
4. 是否有 2 个以上业务 Section、异步依赖、代码编辑、大段输入、复杂联动、多步骤、危险配置、草稿恢复或稳定 URL 需求？是则使用独立页面。

Dialog 必须管理初始焦点、Escape、关闭后的焦点返回、提交与错误。模态 Drawer 用于短暂查看或轻量操作；需要连续切换列表和详情时使用非模态 Side Panel 或 Master–Detail。两者都必须说明需要保留的具体背景上下文。Drawer 必须有明确标题、关闭入口和必要的完整详情入口，且不能嵌套。

列表中的快速详情可以进入 Drawer；包含多个 Tabs、长日志、时间线、可分享内容或稳定 URL 需求的完整详情进入独立页面。全局、工作区与账户配置默认进入独立 Settings；对象级少量配置留在对象编辑上下文；单次参数留在当前任务流程。独立页面必须有返回路径并处理未提交内容。

## 表单结构

先输出“Section → 字段”映射，再画控件。按用户填写顺序和业务语义分组，不按控件类型分组。

- 短小单任务表单不强行分 Section。
- 多 Section 表单通常放独立页面，并保持一个提交边界。
- Section 标题不能替代字段 Label，Placeholder 不能替代 Label。
- 仅在不解释就容易误填时提供一句就近说明。
- 可选高级项可折叠，但非默认值和其中的错误必须可见。
- 提交失败保留输入并定位到具体字段；不要只显示 Toast。

## 主内容结构选择

| 结构 | 适合的用户任务 | 边界 |
| --- | --- | --- |
| Table | 比较多个同类对象的多个字段，或排序、筛选、批量处理 | 出现 3 个以上可比较字段时优先评估；只显示决定操作所需的列 |
| List | 顺序浏览，内容长度差异较大，横向比较较少 | 每项必须有清楚对象、摘要、状态和操作入口 |
| Card | 独立、可整体选择或操作的业务实体 | 必须通过 Card Gate；普通记录列表不能为了好看改成 Card Grid |
| Tree | 文件、组织、权限或分类等真实父子层级 | 没有层级关系时使用 List/Table，不把普通分类强行树形化 |
| Timeline / Event List | 日志、事件、审批或版本的先后过程 | 时间与事件是主要关系；普通记录列表不使用 Timeline |
| Master–Detail | 高频连续处理对象，同时参考列表和详情 | 保持选中与队列上下文；窄屏转为列表 → 详情 |

如果多个结构都可用，以用户需要“比较、阅读、理解层级、理解过程还是连续处理”为判断依据。不要以组件是否现成或视觉是否丰富决定。

## 内容分组选择

| 结构 | 使用条件 | 不应承担 |
| --- | --- | --- |
| Section | 同一任务中需要连续阅读或填写的相关内容 | 独立对象集合或伪装成无边框 Card |
| Tabs | 同一对象或范围内的平级视图，切换后任务上下文不变 | 步骤流程、表单业务分组、必须同时看见的信息 |
| Accordion / Details | 非必需、可独立展开的补充内容 | 必填字段、阻断错误、关键状态和高频操作 |
| Steps | 存在真实先后依赖、后一步需要前一步结果 | 仅因为表单较长或想减少首屏高度 |
| 页面内锚点目录 | 同一长页面的快速定位 | 跨对象、跨任务导航 |

Tabs 通常不超过 5 个。更多时检查能否合并、下沉到子页面或提升为导航；不要把所有被移出的内容塞进“更多”Tab。切换 Tabs 时保留必要状态并提示未保存内容。

## 搜索、筛选与排序

- 只有用户需要从足够大的对象集合中查找时才显示搜索框；不能给每个列表页自动添加搜索。
- 搜索框靠近被搜索的数据，宽度服从工具栏，不占据页面标题区或整行首屏。
- 直接显示 1～3 个高频筛选；高级条件进入有明确名称的 Popover 或筛选面板。
- 已生效条件、数量、单项移除与全部清除保持可见；不能因折叠高级筛选而隐藏当前范围。
- 排序优先通过表头完成，不再增加重复的独立排序控件。
- 非敏感的搜索、筛选、排序和分页尽量进入 URL，使刷新、返回和分享保持状态。
- 真正为空与筛选无结果必须区分；后者保留当前条件并提供修改或清除入口。

## 表格分页布局与行为

- 分页是数据区域的页脚，不是最后一条数据行的附件。列表页以纵向 Flex 组织主工作区，数据区域 `flex: 1`，分页区停靠在可视工作区底部上方，并与页面底边保留约 `24～32px` 安全间距；数据不足一页时，让中间留白自然伸展，不把分页紧贴在最后一行下方。
- 优先使用 `min-height: calc(100dvh - 页头、工具栏和页面间距)` 建立稳定高度，不默认使用 `position: fixed`，避免遮挡数据或在窄屏与缩放时溢出。只有长滚动页需要始终可操作时才使用 sticky，并为最后一行预留不会被覆盖的空间。
- 左侧显示总数和每页数量控件：`共 N 项 · 每页 [10 / 20] 条`。默认每页 10 条；切换为 20 条时保留搜索、筛选和排序，并将当前页重置为第 1 页或收敛到仍然有效的页码。
- 右侧显示翻页控件与 `当前页 / 总页数`。当总页数超过 7 页，或数字分页将明显拥挤时，增加 `跳至 [页码] 页` 输入框；仅接受 `1～总页数` 的整数，按 Enter 或点击“跳转”执行，非法输入就近提示且不改变当前页。
- 搜索或筛选条件改变时回到第 1 页；删除当前页最后一条数据后跳到上一个有效页。服务端分页以服务端返回的总数为准，并在适合分享的页面把 `page`、`pageSize`、搜索、筛选和排序写入 URL。
- 桌面端分页区通常“总数与每页数量在左，跳页与前后翻页在右”；窄屏可以换成两行，但不得隐藏当前页、总页数或前后翻页。所有图标按钮具有 accessible name，页码输入具有可见 Label 或等效可访问名称。

## 操作层级

| 操作类型 | 默认位置与强调 |
| --- | --- |
| 页面主操作 | Page Header 右侧，页面唯一最高强调；只读页可以没有 |
| 当前对象主要操作 | 对象标题或详情操作区，作用对象必须明确 |
| 高频行操作 | 行内直接显示，通常不超过 1～2 个 |
| 低频行操作 | More / Dropdown，使用明确文本标签 |
| 批量操作 | 选择记录后出现的批量工具栏，显示数量与作用范围 |
| 危险操作 | More 菜单或详情末尾的危险区域，必要时确认 |

同一操作不能同时重复出现在页头、工具栏和表格行。刷新、导出、设置与主要业务操作不得使用相同强调级别。纯图标按钮仅用于含义稳定的常见动作，并提供 accessible name 和 Tooltip。

## 反馈与页面状态

| 情况 | 默认反馈位置 |
| --- | --- |
| 字段验证或输入问题 | 字段附近；表单整体错误同时提供可定位摘要 |
| 某个区块加载失败 | 当前区块内，保留其余可用页面 |
| 页面无法继续使用 | 页面级 Alert 或 Error State，并提供恢复路径 |
| 低风险短暂成功 | Toast；结果同时反映到真实页面状态 |
| 需要持续关注的状态 | 页面或对象状态区，不能只依赖 Toast |
| 可撤销操作 | Toast + 真实 Undo；后台不支持时不伪造 |
| 高风险或不可逆后果 | 操作附近说明，并在确认界面明确对象与范围 |

- 首次加载使用贴合真实结构的 Skeleton；后台刷新保留旧数据，只显示局部更新状态。
- 真正为空说明原因并给出一个有权限的下一步；筛选无结果引导修改条件；无权限不能伪装为空数据。
- 局部失败只替换失败区域，不无故清空全页。未知值显示“暂无数据”或“未获取”，不得呈现为 `0`。
- Toast 消失后就无法找回、会影响判断或需要用户行动的信息，不能只放 Toast。
- 空状态保持克制，不使用占据半屏的插画、口号和说明长文。

## 线框交付格式

用真实业务名词和合理长度的示例数据画一个页面，不画组件合集。在线框旁用简短条目说明：

- 任务定义与页面主类型。
- 首屏主要工作区、辅助区和主操作。
- 默认移出的内容及入口。
- Card 使用理由；没有则写 0。
- Modal、Drawer 或独立页面的选择理由。
- 主路径和关键异常状态。
- 窄屏时的内容顺序。

线框只表达区域、顺序与行为，边框不代表实现时需要 Card。请求确认前先复述：用户第一眼看见什么、接下来做什么、完成后到哪里。
