# 实现与交付检查

在实现或最终评审时读取。只验证本次改动影响的范围，但必须证明核心用户任务真实可完成。

## 设计检查

- 页面只有一个与角色任务匹配的主类型，没有把 Dashboard、Editor、Settings 和 Detail 堆在一起。
- 页面类型由主要行为决定；Work Queue 没有因顶部少量汇总而误判为 Dashboard。
- 第一眼能说出页面对象、当前状态、最重要内容和下一步。
- 一个最高强调的主操作；只读页不为凑数添加按钮。
- 首屏符合 1 个主任务、1 个工作区、0～2 个辅助区，没有靠小字或压缩间距塞内容。
- Card 均通过 Gate；普通属性、说明、筛选和 KPI 没有被各自包装。
- 标题尺度克制；中文界面没有重复英文眉题、副标题或装饰翻译。
- 每句说明都提供必要范围、约束、后果或恢复信息；无价值小字已删除。
- 正文、Label 和表格文字至少 14px；关键说明与错误没有使用微小浅灰字。
- 简单任务用居中 Modal，复杂表单用独立页面；每个 Drawer 都有真实上下文依赖理由。
- 快速详情与完整详情分层，持久配置和单次参数具有明确作用域与保存边界。
- Table、List、Tree、Timeline、Master–Detail 与 Card 的选择符合主要任务，没有按视觉偏好套组件。
- Tabs 只承载平级视图，Section 用于连续内容，Accordion 未隐藏必填项或阻断信息，Steps 具有真实先后依赖。
- 搜索确有查找需求；高频筛选数量克制，当前条件可见且返回后合理保留。
- 短数据时分页仍稳定处于可视工作区底部上方，距页面底边约 24～32px，未紧贴最后一行、覆盖数据或在窄屏溢出。
- 每页 10/20 条切换、总数、当前页/总页数与前后翻页可用；页数较多时可输入页码跳转，非法页码不会改变当前页。
- 页面、对象、行内、批量与危险操作层级清楚，没有在多个位置重复同一动作。
- 字段、区块、页面与短暂反馈各自在合适位置；重要结果没有仅用 Toast 表达。
- 多字段表单按业务 Section 分组但不逐组套 Card，提交和错误定位清楚。
- Light、Dark、System、Portal 和图表主题一致。
- 没有渐变、玻璃拟态、发光、巨型 Hero、组件展板或无依据数据。

## 状态覆盖

按当前页面需要覆盖：

- 正常与长文本/极端数据
- 首次加载与局部刷新
- 真正为空与筛选无结果
- 局部/全局错误与重试
- 无权限
- 提交中、成功、失败和输入保留
- 数据陈旧或结果不确定
- 窄屏与浏览器放大
- 浅色、深色和系统主题

未知不能显示为 0，失败不能伪装为空，未接入的功能不能通过假按钮和假 Toast 冒充完成。

## 最小验证路径

1. 从入口找到主内容 → 完成核心动作 → 看见真实结果 → 返回继续工作。
2. 搜索/筛选 → 查看对象 → 返回后保留合理的条件、分页、选中或滚动状态。
3. 用短数据、满页数据和多页数据验证分页位置；切换 10/20 条，输入合法、越界和非整数页码，并检查筛选、删除数据后的页码收敛。
4. 提交失败后输入不丢失，错误能定位，用户可以恢复。
5. 使用键盘进入和退出菜单、Dialog、Drawer；检查 Escape、焦点约束与关闭后焦点返回。
6. 切换 Light/Dark/System 并刷新；检查 SSR 首屏、Portal 和图表。
7. 检查常用桌面、窄屏、200% 放大、长名称与合理大数据量。

运行与改动相关的 lint、类型检查、测试和构建，再进行真实页面走查。只运行构建不等于交互验证完成；只有代码阅读时不能声称视觉验证或可用性测试通过。

## 交付说明

简洁报告：

- 已完成的页面结构和关键内容去向。
- Modal、Drawer、独立页及 Card 的重要取舍。
- 实际运行的验证与结果。
- 受环境、API、账号或工具限制而未验证的内容。

如果只交付线框或视觉稿，明确当前阶段和待确认对象，不把设计产物描述成已实现页面。
