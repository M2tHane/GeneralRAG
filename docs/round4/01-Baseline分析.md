# R4 Baseline 分析：旧 RefusalPolicy 在 Answerability 专项集上的表现

> 撰写时间：2026-09-15。数据来源：eval run `c85c4c50`（72 题 answerability-v1 数据集，
> KB `b78b6fb8` 7 文档/44 分块，HYBRID_RERANK，rerank 阈值 0.65 / cosine 阈值 0.30，真实模型）。

## 1. 旧策略混淆矩阵（判定口径：回答以拒答文案开头 = refused）

```text
TP=34  FP=18  FN=0  TN=20
False Answer Rate = FP/(FP+TN) = 18/38 = 47.4%
False Refusal Rate = FN/(FN+TP) = 0/34 = 0.0%
```

检索本身很好：Hit@1=0.882、Hit@3/5=1.0、MRR=0.936、Recall@5=1.0——
**问题不在召回与排序，全部 18 个 FP 都是"检索到了相关分块但证据不包含完整答案"**。

## 3. 关键结论：不存在安全的 highThreshold

不可回答题的 rerank 最高分达到 **1.000**（与可答题满分完全重合），
8 道 PARTIAL_EVIDENCE 题 rerank ≥ 0.976。阈值扫描：

| 阈值 T（低于 T 拒答） | FP | FN |
| --- | -- | -- |
| 0.65（现行） | 18 | 0 |
| 0.85 | 11 | 1 |
| 0.95 | 8 | 5 |
| 0.97 | 8 | 8 |

**任何单阈值都无法同时压低两类错误**：PARTIAL_EVIDENCE 的分数分布与可答题
几乎完全重叠（这类题检索到的正是答案所在的数据表，只是问题要求的维度超出表内容）。
原方案"score ≥ highThreshold 直接生成"被数据否定——若坚持 high 阈值直答，
即使 high=0.995 仍有 5 道 PARTIAL_EVIDENCE 会漏进 FP。

## 4. 采用的门控（数据驱动修订）

```text
score < lowThreshold（0.65 rerank 口径 / 0.30 cosine 口径，沿用旧校准）
    → LOW_SCORE_REFUSAL（不调 Judge，省成本）
其余（灰区 + 高分全部）
    → EvidenceSufficiencyJudge
```

依据：

1. 低于 0.65 的不可答题有 20/38（53%），这部分零成本拒掉，且可答题
   min=0.747，low=0.65 误拒风险低（0.65~0.747 有 0.097 的安全带）；
2. 灰区（≥0.65）= 52/72 题（72.2%）需要调 Judge——两阶段门控的成本节约有限，
   但**保留了低分快速通道**，且这是数据决定的形态，不是拍脑袋；
3. Judge 输入用最终生成用的同一份 Context（与生成一致性）。

## 6. FN（0 条）

旧策略没有任何误拒——因为阈值 0.65 偏宽松 + PARTIAL_EVIDENCE 把 FP 顶到最高分。
新策略引入 Judge 后的风险方向是 FN 上升（Judge 偏保守把可答题拒掉），A/B 时必须监控。

## 7. 对 Judge 失败策略的数据支撑

Judge 不可用时的降级：**failOpen（放行生成）会回到旧策略行为**——灰区 52 题里
FP 率按 Baseline 为 18/52≈35%；**failClosed（拒绝）则把这 52 题全部拒掉**，
其中 34 题可答 → FRR 瞬间 100%。两者都极端。折中（按用户倾向的保守方向 +
可用性平衡）：**Judge 失败 → 回退旧阈值行为（rerank 阈值 0.65 比对）并显式标注
JUDGE_DEGRADED**。即"灰区低段退回旧策略、不虚构判定"，误判上界=旧策略本身，
且降级可观测（Eval/Debug 落库）。这不是 failOpen 也不是 failClosed，而是
"degrade to previous policy"——语义上等价于"没有 Judge 时的系统原有能力"。

## 8. 成本预估

- Judge 调用率 ≈ 72%（52/72，lowThreshold=0.65 时）
- Judge 用同一 chat 模型（deepseek-v4-flash），输入 ≈ 问题 + 6000 字符上下文，
  预估 +0.8~1.5s/题；低分题（27%）反而变快（不生成）。
