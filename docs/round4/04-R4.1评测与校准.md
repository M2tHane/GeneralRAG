### 选定：0.75，依据

1. **FAR≤3% 不可达**（如实说明，不伪造精度）：unanswerable 侧有 6 题落在 0.95–1.0
   （全部是 PARTIAL_EVIDENCE 多子问题题，检索必然命中），任何阈值都拦不住，
   必须靠 Judge 语义判定——这正是 R4 引入 Judge 的原因，与 docs/round4/01-Baseline分析.md
   结论一致。纯阈值扫描无一点 FAR≤3%，该规则在本数据集上无统计意义上的解。
2. **0.65→0.75 的边际收益**：直拒净增 3 个正确拒答（seq26 Vibur maxIdleTime 0.7479、
   seq52 HikariCP keepaliveTime 0.6949、seq65 Kafka assignment strategy 0.6836——
   三题均无对应语料），FP 17→14；代价仅 seq35（0.7467，可答）落入直拒——该题恰是
   R4 残留 FN（Judge 本就误拒，docs/round4/02-实施记录.md §7），阈值上移使其损失
   从"Judge 判定"变为"确定拒答"，总 FN 数不变。
3. **0.75→0.78+ 的边际收益不选**：FP 再减 3（14→11），但每题都是把
   "Judge 灰区语义判定"换成"一刀切直拒"——seq33（always 刷盘 QPS）、seq34（connectionTimeout
   调优值）、seq50/54（部分子问题语料可答）交给 Judge 有答对机会；且 FRR 已达上限
   （seq35 一题），继续上移只降 Answer Rate 不再改善 FAR 的结构性部分。
4. **judge 工作量**：0.75 时 48/72 题进 Judge（66.7%），与 R4 实测 72.2% 相当，
   不增加成本。

一句话：**0.75 是"不新增 FRR 的前提下，把确定无答案题尽量挡在 Judge 之前"的最大步长点**；
FAR 的剩余部分（PARTIAL_EVIDENCE@1.0）只有 Judge 能处理。

## G. 真实模型并发冒烟（bulkhead 参数验证）

**方法**：`scripts/smoke_concurrency.py`（已入库）经 `/api/v1/qa/stream` SSE 走完整
Answerability 路径（非直调 Judge SDK）；8 道 rerank 分 ≥0.65 必进 Judge 的题，
1/4/8 并发各 16 请求（2 轮 × 8 题）；生产配置 maxConcurrentJudges=4、
bulkheadWaitMs=500、judgeTimeout=15s。

| 并发 | 请求 | 成功 | TIMEOUT | OVERLOADED | MODEL_ERROR | INVALID_RESPONSE | P50 | P95 | wall |
| - | - | - | - | - | - | - | - | - | - |
| 1 | 16 | 16 | 0 | 0 | 0 | 0 | 4292ms | 66291ms* | 173.7s |
| 4 | 16 | 16 | 0 | 0 | 0 | 0 | 3988ms | 19714ms | 28.0s |
| 8 | 16 | 16 | 0 | **6** | 0 | 0 | 5513ms | 16829ms | 16.8s |

\* conc=1 的 P95 长尾是单请求生成端 66s 长尾（deepseek 长回答），与 Judge 无关
（该请求 Judge 段正常）；重复跑大概率漂移，仅如实记录。

**解读**（数据依据，非感觉）：
- **conc=1/4：0 OVERLOADED**——maxConcurrentJudges=4 在 4 并发内不产生排队损耗；
- **conc=8：6/16（37.5%）OVERLOADED 快速降级**——每请求 wall≈5.5s（Judge 2.8s + 生成），
  8 并发瞬时在途 Judge ≈ 8×(2.8/5.5) ≈ 4.1 > 4 许可，属**预期 backpressure** 而非 bug：
  降级请求 500ms 内拿到明确 OVERLOADED 原因并退回旧阈值行为（rerank 分 ≥0.65 → 放行生成），
  无一请求失败或超时；同时印证 R4 数据"QPS 32、判定 2.6s"下 4 路并发的排队期望（≈5.2s）
  在真实长回答场景被高估——生成不占 Judge 名额，4 容量对应约 7-8 的稳态并发上限。
- **不建议为消除 OVERLOADED 调大 semaphore**：本地单模型（Judge 与生成同源
  deepseek-v4-flash-0731）在 conc=8 时延迟已恶化（P50 5513ms vs 3988ms），提高并发只会
  把恶化转移给生成端；OVERLOADED 是显式、快速、可观测（reason 前缀）的反压信号。

## H. 结论

**已被数据证明**：
1. 可比环境重建成功：baseline v1 口径与 R4 原始记录逐位一致（§C）。
