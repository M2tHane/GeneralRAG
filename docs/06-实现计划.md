# 通用知识问答 RAG 第一版 — 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task under the parent workflow's approval gates. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可本地运行、可演示、可评测的知识问答 RAG 第一版：文档入库（解析→清洗→分块→向量化→入库）→ 向量检索 → SSE 流式回答与来源引用 → 检索调试 → 基础评测。

**Architecture:** Maven 单模块 `rag-server`（Spring Boot 3.3.x，按包边界隔离 api/ingestion/retrieval/llm/eval/storage/domain/config）+ Next.js App Router 前端 `rag-web`。持久化：MySQL 8（Flyway，11 张表）+ Elasticsearch 8（分块正文/元数据/向量，kNN+filter）+ MinIO（源文件与解析产物）。跨存储删除用 cleanup_task 补偿表异步收敛。权威依据：`contracts/openapi.yaml`（API 边界）、`docs/03-技术路线.md`（架构理由）、`docs/01-需求理解.md`（验收标准）、`prototype/DESIGN.md` + `prototype/*.html`（已批准 UX，信息层级与交互语义必须保留）。

**Tech Stack:** Java 17 / Spring Boot 3.3.x / LangChain4j 1.x（OpenAI 兼容客户端）/ elasticsearch-java 8.14 / Spring Data JPA + Flyway 10 / minio-java 8.5 / springdoc 2.6 / JUnit5 + Testcontainers / openapi-diff；前端 Next.js 14+ / React 18 / TS / Tailwind / shadcn/ui / TanStack Query + Table / openapi-typescript。

**环境适配（对路线文档 §1 的已批准偏差）**：本机 JDK 为 17（无 21），`spring.threads.virtual.enabled` 不启用（Java 21 特性），改用固定大小线程池（ingestion worker 池 + SSE 专用 executor），行为等价、不影响契约。`maven.compiler.release=17`。

**验证环境事实（已核实）**：JDK 17.0.19、Maven 3.9.16、Docker 29.6.1（Testcontainers 可用）、Node 24 + pnpm。模型服务在测试中以 MockWebServer 替身提供；真实模型服务仅在最终本地启动验证时由用户环境变量提供。

**总验证策略**：每任务先跑最窄检查（单测/编译），集成验证用 Testcontainers（mysql:8、minio、elasticsearch:8；ES 集成测试若本地拉取含 IK 的镜像失败，允许退回官方镜像 + `standard` 分析器并如实记录）；契约漂移用 springdoc 导出与 openapi-diff 比对；SSE 用 OkHttp EventSource 真实流测试；前端用 vitest + Playwright 主旅程。禁止把"代码看起来对"当作验证通过；所有证据记录进 `docs/06-测试报告.html`。

### Task 3：ingestion 入库流水线

依赖 Task 2。包边界：不得 import retrieval/llm。

- [ ] 步骤：`parse/DocumentParser` 接口（输入文件流+类型，输出 `ParsedDocument{text, pages:[{no,text}], headings}`）+ PdfBoxParser（文本层检测：首页无文本 → `SCANNED_PDF_NOT_SUPPORTED`）/ MarkdownParser（按 # 层级提标题路径）/ TextParser。
- [ ] 步骤：`chunk/Chunker` 接口 + 两个实现（语义与原型一致）：
  - `LengthOverlapChunker`：固定长度切分、相邻块重叠 overlap 字符、titlePath=文档名、page=null；
  - `StructureChunker`：按标题/段落边界切分，单块超 maxLength 再按长度截断，保留标题路径，PDF 记起始页。
  - 共同约束：chunkId 确定性 `{docId}-c%04d`；空文档 → 0 块不报错；重叠≥块长 → 启动期/参数校验拒绝。
- [ ] 步骤：`ingestion/IngestionTaskManager`：固定线程池认领 QUEUED 任务；阶段推进 PARSING→CLEANING→CHUNKING→EMBEDDING→INDEXING→COMPLETED，每阶段先落 task.stage 再执行；失败捕获→FAILED+failureStage/Reason（ErrorCode 枚举+人读文案）；重试从 failureStage 继续（PARSING 完成标志=parsed.txt 存在；CHUNKING 起直接重建，ES 先删后写幂等）；`ApplicationReadyEvent` 恢复：QUEUED/RUNNING→QUEUED(attempt+1)。
- [ ] 步骤：`ingestion/CleanupService`：@Scheduled(fixedDelay=30s) 扫 PENDING/FAILED cleanup_task → ES delete / MinIO removePrefix；成功 DONE，失败 FAILED+last_error+attempts+1；删除 KB/文档时由 service 层写入 cleanup_task 行。
- [ ] 步骤：单测 `chunk/ChunkerTest`（边界：空文本、重叠≥长度、超长标题路径、PDF 页码归属）、`IngestionTaskManagerTest`（状态机迁移表：非法迁移拒绝、失败重试续跑不重复解析——用 spy 验证 PARSING 未重跑）。

- [ ] 验证：`mvn test -Dtest='ChunkerTest,IngestionTaskManagerTest,IngestionPipelineIT'` 通过。

### Task 5：retrieval + llm——问答链路（SSE）

依赖 Task 2。与 Task 3/4 可并行（包不相交；共享 storage/domain 只读）。

- [ ] 步骤：`config/ModelClients`：按 RagProperties 构造 `OpenAiStreamingChatModel`/`OpenAiEmbeddingModel`（LangChain4j，自定义 baseUrl/apiKey/timeout）；`startup-check=true` 时 ApplicationRunner 调一次 embedding 并比对 dimensions（失败→启动失败，信息指出具体环境变量）。
- [ ] 步骤：`retrieval/RetrievalService`：question→embedding→`EsChunkIndex.knnSearch`（filter kb_id）→**已删文档有效性过滤（KB-9"删除后检索不再命中"：kNN 命中后按 doc_id 批量查 document 表，过滤主档已删除的 hit，避免 30s cleanup 周期内的"幽灵命中"）**→minScore 应用侧过滤→`RetrievalHit{rank,chunk,score,passedThreshold}`；`retrieval/Reranker` 接口 + NoOp 实现。
- [ ] 步骤：`retrieval/ContextAssembler`：按分数序拼接「【文档 N】名称（页码）> 标题路径\n正文」，超 max-context-chars 截断并标记 CONTEXT_TRUNCATED。
- [ ] 步骤：`llm/PromptAssembler`：双区结构（对话历史区=最近 max-history-messages 条，仅连贯性；文档证据区=上下文），系统指令明确「仅依据文档证据回答；证据不足时明确说明无法依据当前资料回答；禁止编造引用」（QA-3/QA-6）。
- [ ] 步骤：`llm/ChatStreamService` + `api/qa/QaController`：
  - POST /api/v1/qa/stream → SseEmitter（text/event-stream；心跳 :ping 15s；X-Accel-Buffering: no）；SSE 专用 executor 上限（默认 32 并发流）与超载行为（超出→503 SERVICE_UNAVAILABLE）；
  - 事件序列：stage(RETRIEVAL_STARTED) → stage(RETRIEVAL_COMPLETED{detail:"命中 N 块 · Xms"}) → stage(GENERATION_STARTED) → token(delta)* → citations(本次实际 hits；无通过阈值时=[]) → done{messageId,elapsedMs}；
  - 用户消息与助手消息落库（status COMPLETED/ERROR/CANCELED）；
  - clientRequestId 活跃流登记→重复 409 STREAM_ALREADY_ACTIVE；`POST /qa/cancel` 202（终态 canceled）；emitter onError/onTimeout→canceled 并停止生成；模型无 token 超时（timeout-seconds）→ error MODEL_TIMEOUT；模型异常→error MODEL_UNAVAILABLE/RETRIEVAL_FAILED。
- [ ] 步骤：单测 `ContextAssemblerTest`、`PromptAssemblerTest`（历史≠证据断言）；集成测试 `qa/QaStreamIT`（MockWebServer 假模型：happy 序列断言 stage→token*→citations→done；模型 500→error；客户端中途断连→canceled 落库；重复 clientRequestId→409；minScore 过滤后 citations=[]；**删除收口用例：上传文档完成入库→DELETE 文档→立即提问→断言该 doc 不出现在 citations/hits**）。
- [ ] 验证：`mvn test -Dtest='ContextAssemblerTest,PromptAssemblerTest,QaStreamIT'` 通过。
