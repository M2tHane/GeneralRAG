# 01 需求理解 — 通用知识问答 RAG（第一版）

> **基线说明**：本文内容来自用户启动提示词，属用户已明确批准的需求基线。用户通过启动提示词直接确认需求，未执行需求访谈与独立评审；本文仅做结构化整理，不扩大、不缩小范围。后续两轮为路线图，本轮不实现。

## 1. 项目定位

- 项目名称：通用知识问答 RAG。
- 目标：可本地运行、可演示、可评测的知识问答系统，覆盖「文档入库 → 检索 → 回答 → 来源追溯 → 效果评测 → 问题优化」完整闭环。
- 首个业务场景：**团队技术文档与故障手册问答**；数据结构不写死具体行业。示例资料使用明确标注的模拟技术文档，不虚构真实客户或生产使用情况。
- 第一版默认：单用户、单工作空间、支持多个知识库。

## 2. 技术方向（Stage 3 细化）

- 后端：Spring Boot + LangChain4j；存储：Elasticsearch（分块/元数据/向量、后续混合检索）、MySQL（知识库、文档、任务、会话、评测元数据）、MinIO（源文件与解析产物）。
- Redis/Redisson：仅在缓存或多实例协调有实际需求时引入，不为凑技术栈而加。
- MinerU：后续复杂 PDF/扫描件解析能力，通过适当服务边界集成；不假设它统一处理所有格式。
- BGE-Reranker：第二轮重排候选方案，Stage 3 核对运行资源与接入方式。
- 生成模型与 Embedding 模型提供可配置接口；具体模型、服务地址、部署方式在 Stage 3 确定。不默认本机有 GPU，不强制全部模型本地部署。
- 前端新建时采用 `enterprise-frontend-design` 默认技术体系。

## 3. MVP（第一版必须实现）

### 3.1 知识库与文档管理

| # | 要求 | done-when（验收标准） |
|---|------|----------------------|
| KB-1 | 创建、重命名、删除知识库；删除时明确影响范围并确认 | 删除确认框列出将清除的文档/向量/会话影响，确认后知识库及其检索内容不可再用 |
| KB-2 | 支持 PDF、Markdown、TXT 上传；PDF 第一版仅承诺文本型 PDF，扫描件明确提示暂不支持 | 上传非文本型 PDF 时给出明确"暂不支持"提示而非静默失败 |
| KB-3 | 上传后异步执行「解析 → 清洗 → 分块 → 向量化 → 入库」，接口不等待整个流程 | 上传接口立即返回任务受理；进度通过任务状态查询获得 |
| KB-4 | 展示文档状态、当前处理阶段、失败原因和重试入口 | 失败文档可见失败阶段与原因，并可触发重试 |
| KB-5 | 文档列表、详情、解析文本预览、分块预览和删除 | 每个入口均可操作且数据真实反映处理产物 |
| KB-6 | 两种可解释分块策略：按长度+重叠；按标题/段落结构+最大长度 | 分块配置可选、可解释，分块结果可预览 |
| KB-7 | 保留来源文件、标题路径、分块标识、可获得的页码等元数据，支持回答引用追溯 | 任一引用可回溯到文档与具体分块 |
| KB-8 | 基于知识库范围与文件内容哈希去重；持久化任务状态、唯一约束、幂等写入，防重复分块/向量化 | 同一文件重复上传有明确去重行为；任务中断重试不产生重复分块 |
| KB-9 | 失败任务可重试且复用已完成阶段；删除后内容必须退出检索；跨存储清理失败可追踪、可重试 | 重试不重做已完成阶段；删除文档后检索不再命中其内容 |

### 3.2 知识问答

| # | 要求 | done-when |
|---|------|-----------|
| QA-1 | 选定知识库后提问，检索限定在该知识库内 | 跨库文档不出现在检索结果与引用中 |
| QA-2 | 第一版实现向量检索基线，召回数量等参数可配置 | 检索参数可配置并实际生效 |
| QA-3 | 多轮会话；区分会话历史与文档证据，不把用户先前说法当知识库事实 | 回答引用只来自文档证据；会话历史只用于对话连贯性 |
| QA-4 | SSE 返回实际处理阶段、回答内容、结束/失败事件；不使用虚假进度百分比 | 事件流中的阶段均为真实发生的阶段 |
| QA-5 | 回答附带来源引用，可查看对应文档与分块；来源必须来自本次实际检索结果 | 每条引用可点开对应分块原文 |
| QA-6 | 资料不足时明确说明无法依据当前资料回答，不伪造引用 | 资料外问题得到"无法回答"类回复且无引用或仅列出实际检索命中 |
| QA-7 | 新建、切换、删除会话和重新提问 | 会话管理操作均可用 |
| QA-8 | 正确处理模型超时、检索失败、流中断、取消和重复提交；保留必要输入并提供恢复路径 | 异常场景下用户输入不丢失，可重试或恢复 |

### 3.3 检索调试

独立调试页面，展示：查询内容与生效检索配置、命中文档与分块、排名与检索分数、各阶段耗时、实际送入模型的上下文，以及未召回/上下文不足/引用错误等问题线索。普通问答页不默认展开这些技术细节。

done-when：用任一问题在调试页可完整看到上述信息，且与问答页本次实际执行一致。

### 3.4 基础评测

| # | 要求 | done-when |
|---|------|-----------|
| EV-1 | 人工核对的样本集：问题、参考答案、相关文档/证据、是否可回答标记 | 样本集存在且字段完整 |
| EV-2 | JSON/CSV 导入样本并运行基础评测；完整管理 UI 留到第二轮 | 通过导入文件可发起并完成一次评测运行 |
| EV-3 | 记录明确 K 值的 Hit@K、单次耗时、实际回答和来源，支持人工标记失败原因 | 评测结果含上述字段并可人工标注 |
| EV-4 | 保存数据集版本、模型、检索参数、分块配置和运行时间，保证实验可对比 | 两次运行可按保存的配置区分 |
| EV-5 | 样本覆盖直接问答、术语差异、多轮追问、资料外、易混淆问题 | 样本集包含上述类别 |
| EV-6 | 区分调优集与独立测试集 | 数据集有类型标记且不混用 |

## 4. 显式非目标（Won't now / 第一版不做）

- 登录注册、多租户、复杂 RBAC、计费。
- 插件市场、Agent 编排、微服务体系。
- BM25/RRF/BGE 重排、意图识别、查询改写（第二轮）。
- 完整评测管理 UI、八项指标、逐题对比（第二轮）。
- Word/Excel/CSV 解析、扫描件解析、文档多版本管理（第三轮）。
- 多实例分布式协调、多人权限模型（有需求再做）。
- 评测对比页面不在第一版放置无功能入口。

## 5. 重要业务规则与边界

1. 去重维度 = 知识库范围 + 文件内容哈希。
2. 引用与证据只来自本次实际检索结果；会话历史 ≠ 文档证据。
3. SSE 只报真实阶段，禁止虚假进度。
4. 跨存储（MySQL/ES/MinIO）不宣称单事务原子提交；删除清理失败必须可追踪、可重试。
5. 调优集与独立测试集分离，不得反复针对同一批测试题调优后宣称泛化提升。
6. 图片中的「100 条样本、Hit@K 75%→99%」是他人的展示案例，不是本项目结果或必须指标；一切数字以本项目实际实验为准。
7. 不预先书写「工业级」「生产验证」等未经证明的结论；不伪造运行时间或评测成绩。

## 6. 前端与原型要求（第一版页面范围）

1. 知识库与文档管理；2. 文档详情/解析结果/分块预览；3. 带来源引用的知识问答；4. 检索调试。

统一要求：中文界面，蓝白冷灰、商务简洁、清晰字号，Light/Dark/System；首屏聚焦当前主要任务；高级参数进设置/调试页；按任务选择 Modal/Drawer/Side Panel/独立页面；表格分页稳定靠近工作区底部（24–32px 底部间距，10/20 条每页，多页时支持页码跳转）；原型交互真实改变模拟数据；展示加载/空数据/筛选无结果/失败重试/提交中/长内容等状态；模拟状态开关放独立预览工具区（默认收起）；每张视觉预览只展示一个完整页面；设计决策只维护在 `prototype/DESIGN.md`。

## 7. 验收与交付原则

- 真实文档可完成上传、处理、检索、回答与来源查看。
- 重复上传、失败重试、删除后检索、无答案问题、流式异常有可验证行为。
- 第一版样本评测可运行并保存真实结果与配置。
- 原型模拟数据、自动化测试替身、真实集成验证分别说明，不互相冒充。
- 提供清晰本地启动方式、配置示例和真实执行的验证报告；密钥走环境配置，不入仓库。

## 8. 路线图（本轮不实现，仅记录）

- **第二轮 检索与效果优化**：BM25+向量 KNN 双通道、RRF 融合、BGE 重排；按 BadCase 增加意图识别/查询改写/多轮独立化（不无条件增加模型调用）；完整评测页面（两次运行逐题对比、指标变化、BadCase 归因）；八项指标（Hit@K、Recall@K、MRR、上下文 Precision/Recall、忠实性、正确性、相关性，LLM 裁判保留人工抽查）；分步对照实验记录效果/延迟/成本。
- **第三轮 解析与可靠性增强**：格式扩展至 PDF/Word/Excel/MD/TXT/CSV 并按格式选解析器；按实验结果扩充分块策略；接入复杂 PDF/扫描件解析（表格、标题层级、来源定位）；文档多版本管理与发布切换；向量化失败补偿、历史版本残留清理、异常恢复；需要多实例时再引入分布式协调（锁不替代幂等与唯一约束）；明确跨存储最终一致性/重试/补偿；有多人需求时再设计权限模型且权限约束进入检索边界。
