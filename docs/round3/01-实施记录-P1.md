## 1. 交付内容

### 1.1 Word / Excel / CSV 解析（P1-1）

| 文件 | 说明 |
| --- | --- |
| `rag-server/.../ingestion/parse/DocxParser.java`（新） | POI XWPF。Heading 1-6/标题 1-6 → ATX；表格 → Markdown 管道表；空段落丢弃；纯图片文档显式失败 |
| `rag-server/.../ingestion/parse/XlsxParser.java`（新） | POI XSSF。每 sheet → `## sheet` + 管道表；DataFormatter 取显示值（防 Excel 序列值泄漏）；跳过全空行/列；全空工作簿显式失败 |
| `rag-server/.../ingestion/parse/CsvParser.java`（新） | 简化 RFC4180（引号包裹 + `""` 转义）；→ 单块管道表；空文件/单行文件显式失败 |
| `pom.xml` | 新增 `org.apache.poi:poi-ooxml:5.3.0` |
| `FileType.java` | + DOCX / XLSX / CSV |
| `ObjectStore.java` | 扩展名白名单 + docx/xlsx/csv Content-Type |
| `DocumentService.verifyMagicBytes` | docx/xlsx 走 ZIP 容器魔数（PK\x03\x04）；旧版 .doc/.xls 被拦截并给出明确提示 |
| `ParsedDocument.fromPersisted` | DOCX/XLSX 按 MD 重建标题结构，CSV 纯文本——重试从 CHUNKING 续跑与首次解析等价 |
| `ParserRouter` / `IngestionTaskManager` / `ErrorCode` | 路由、源对象扩展名映射、415 默认文案同步扩展 |
| `contracts/openapi.yaml` | `Document.fileType` 枚举 + DOCX/XLSX/CSV；上传接口描述、415 语义同步 |
| `rag-web` | 上传 accept/校验提示支持新格式；`FILE_TYPE_LABEL` + Word/Excel/CSV |

设计要点：**三种新格式都归一为 Markdown 风格文本**，使 StructureChunker 的标题路径
能力零改动复用（docx 的标题样式、xlsx 的 sheet 名都成为 titlePath 层级）。

### 1.2 稳定分块锚点键（P1-3）

| 位置 | 说明 |
| --- | --- |
| `EvidenceMatcher.contentHashOf(String)` | 规范化（strip + 内部空白折叠单空格）SHA-256 前 16 hex；唯一入口 |
| `EvidenceMatcher` 锚点优先级 | `contentHash` → `chunkId` → `titlePath` → `anchorPath`，精确相等，不回退 docName |
| `EvalRunExecutor` retrieved 快照 | 新增 `contentHash` 字段（现算自分块正文） |
| `EvalRunViewService` | `CandidateRef` 扩展为 `(contentHash, chunkId, titlePath)`，快照复算与检索判定同口径 |
| `contracts/openapi.yaml` | `EvidenceRef.contentHash`、`EvalHit.contentHash` 新增并注明规范化规则 |

价值：数据集锚点与「文件名 + 分块策略」解耦。文档改名、重入库导致 chunkId 变化后，
数据集无需重建仍可判定命中——这是 P3（文档多版本）的前置。

## 3. 过程问题与修复

1. **运行中后端仍是旧构建**：真实上传报 415 旧文案 → 停进程、重编译、以原环境变量重启
   （`spring-boot:run`），embedding 探活通过后重测。
2. **contentHash 生成的模拟漂移**：最初以 Python 模拟分块产出的哈希与 POI 真实产物存在
   细微空白差异风险，最终改为「入库后拉取服务端真实分块现算哈希」回填数据集（已固化到
   README-formats §2 流程）。
3. **上传默认策略掩盖结构解析**：LENGTH_OVERLAP 下 titlePath 全为文件名；改用 STRUCTURE
   重传后标题路径正确。评测前置条件已写明必须 STRUCTURE。

## 4. 未验证 / 已知边界

- docx 的文本框、图片内文字不提取（与 PDF 文本层口径一致，未单独验证）；
- xlsx 公式单元格取「显示值」，缓存值缺失场景（如未被 Excel 打开过的公式文件）未验证；
- CSV 含换行的引号字段不支持（简化 RFC4180，与数据集 CSV 口径一致）；
- 新格式未覆盖 `.docx` 内嵌图表、合并单元格（单元格取左上值）；
- P1 语料仅各 1 篇（计划文档写「≥2 篇」），评测区分度依赖题目结构差异补足；
  第 2 篇语料补齐前，跨格式结论保持谨慎。
- 前端上传入口已支持新格式，但未做浏览器端到端走查（本轮验证以 API 层为准）。
